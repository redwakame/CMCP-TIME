**0.1.1 is more than a setup-documentation update.** It brings together cumulative source-preserving continuity work and four scoped maintenance fixes. The comparison below focuses on user-visible behavior; engineering detail remains in the original release documentation.

| Area | Foundation in 0.1.0 | Increment in 0.1.1 |
|---|---|---|
| Sources and time | Original records, roles, timestamps, source relationships and bounded reading. | The foundation remains. New derived organization does not replace originals. |
| Plans and reports | Existing temporal, source and continuity entries. | Cumulative S1/S1-R1 work separates current plans from user reports, rather than treating intent as an event that has already happened. |
| Scoped changes and reasons | Source retrieval existed; that does not establish the later representation and verification. | Conditions and explicitly named targets are represented separately. Revise the specified part, retain the rest and distinguish added reasons, priorities and explicit withdrawal. |
| Setup | The interactive wizard and `--answers` already existed. | Explicit non-TTY/EOF handling. Batch pipes remain unsupported; use `--answers`. Without Codex selected, setup does not probe it or tell you to launch it. |
| On-demand current state | Existing source and control foundations. | Better feedback and complete result pagination for specified mixed report/instruction cases, while retaining unread material and real ambiguity. |
| Proactive status | OFF on first use, with Buffer/Pin/quiet hours and authorization controls. | Distinguishes configured values, effective executor, delivery connection and eligible candidates. No new general proactive policy. |
| Release and documentation | Four-language docs, diagrams, formal GitHub/npm 0.1.0. | Formal GitHub 0.1.1, cumulative sources and corrected release mapping. npm remains a separately verified channel. |

## What stays the same

Derived state does not replace original records. The host model still reasons. Codex is optional. Saving, tracking, quiet hours and external execution authority remain separate. Apache-2.0, attribution to redwakame and upstream notices remain.

## Scoped success is not universal completion

H4 verified the three specified reports and complete projection pagination in a new Session. The normal chain did not exercise the resolution branch; 13 fixed-source checks cover it separately. Additional r8 did not reach the model, so this is not all-selected READ-ALL. C27 163/236 capacity limits and the missing historical receipt preimage remain documented.

This version does not add complete Dots/Muse/Grok Bot lifecycles, broad cloud deployment, audio/video, vector retrieval or a full 24/7 agent. It does not establish superiority over native memory. Four-language documentation is not four-language model-behavior certification.

## Get the version and update

Use the [homepage’s fixed npm version](../README.md#get-started) or the [installation guide](npm-installation.md), and select persistent directories. Back up before updating; do not remove History to upgrade. Installing the package and updating a host attachment are separate operations.

The GitHub and npm artifacts can differ in publication settings and documentation. Consult their respective release records for executable-content and source mapping. The same version number does not mean byte-identical archives; `latest` is not a fixed source identity.
