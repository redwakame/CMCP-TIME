# CMCP-TIME 路線與正式版範圍

## 0.1.1 GitHub-only：S1／S1-R1 與既有功能維護

本次只處理初始化／無 Codex 入口、混合回報與指令的按需狀態處理、主動配置與有效派送的說明，以及交付回執引用更正。沿用已驗 S1／S1-R1，受影響入口與實際驗收結果由同版維護報告分項列明，不以程式存在或 `ready` 代替語意／送達／執行授權。

初始化保留互動與 `--answers`；非互動缺答案明確拒絕，未選 Codex 不探測或啟動它。狀態分開設定、安裝、宿主接線與正式來源可讀性。按需投影的用途回饋明示合法類型與正式來源 ref，完整結果沿既有有界分頁取得；僅以可逆參照共用重複查證物件，不裁原文或提高容量。首次主動仍為 OFF；低層閒置值不代表閒置後必發送，實際候選、期限、控制與已接送達入口另列。

Dots／Muse／Grok Bot 新整合及跨環境生命週期暫緩，等待產品增量價值與實際接點確認；原六方向、既有跨宿主／遠端能力及完整代理長期目標保留。0.1.1 由 GitHub 的固定 tag／Release 提供來源與正式 tgz；npm 此次不更新，既有 0.1.0 與標籤保留。套件保留 private:true 防止誤發 npm，使用者的日常部署不會自動切換。發布位元組、公開讀回與平台證據見 Release 外置回執。

## 0.1.1 納入的 S1／S1-R1：日常事件接續

正式 0.1.0 及其公開提交保持。0.1.1 的 S1 增量以按需接續投影重用正式 reader、原文、事件關係與有界工作集；普通原文仍不自動設定 eventKey，不強迫每輪分類或呼叫第二模型。具體使用入口與來源契約見[按需接續](daily-continuity.md)。

已實作來源逐字引文、原角色／原時間、修訂／提案／明說理由分層、取消及來源變版守護；共用 CLI 與最小介面可查看本對話投影。S1-R1 的查詢投影 v3 以精確原文作計畫基底，局部修改逐段保留、替換或撤回；暫停／取消是獨立狀態，不移除未改條件。理由新增、優先、取捨與明示撤回保持分開；原理由綁定原基底，新的修改原因另綁該次正式來源與版本，不由目前參數倒填原因。缺理由欄位可沿具名更正修正，未提供不等於不存在；v1/v2 仍相容。當輪已保存原文可經正式票券納入閱讀。宿主回答前的通用責任作用於實際修訂回合，不事後改寫原答。Hermes 的有限閱讀階段協助核對官方直接／lazy 工具入口與正式登錄，不改原生工具或模型策略。正式讀完與模型材料覆蓋分列，容量不足須回 partial，不能用原文已讀掩蓋必要材料未送達。結構、來源、語意與執行授權分開，不由工具 ready 代替驗收。

v3 另分計畫基底與有正式引用的修改／理由證據。證據保留來源、角色、原時間及關係，但不另成待執行計畫；真正獨立的計畫仍須保留。省略角色的舊提案維持相容行為，不會自動改寫舊投影；新的正式投影需明確提出角色並通過來源與關係檢查。

新提案可由 v6 型別入口明示各計畫的修改鏈，再編譯成同一來源驗證契約；回報與提案保持分區。精確重疊的 `planScopeReview` 只指出一項修改與另一項目前表示共用哪些來源區間，不直接推定兩者作用於同一對象；同條件的矛盾由宿主核對原話後修正，獨立條件保持。結構通過、待核對疑點、來源正確、自然語意及執行授權分列。Hermes 正常入口的單輪期限、取消與實際釋放回執保持有界，不以晚到答案冒充已完成。

本輪新增的有界修復責任包括閱讀票券內的來源身分、必要中間 User 修訂原件，以及明示理由效力與優先的分工。票券 ref 不能跨次沿用；缺少必要原件時仍須正式補讀，不把已讀所選集合冒稱材料已齊。具名更正回饋保留逐字來源校驗，不自動猜測替代來源或全庫擴讀。這些實作是否改善中間回合，仍以同版真宿主與未參與調整變體裁決。

本輪以隔離 Harness SDK 與 Hermes CLI 作基準及候選對照；實際原答、模型材料、平台、失敗與成品裁決由同版本 S1 本機交付報告列明，不由程式存在或此路線表預填通過。日常 Desktop 不自動更新；Codex／MCP 接線採受影響定點回歸，不擴稱本輪所有具名宿主已實測。

剩餘依賴包括更廣自然歧義與語意穩定性、超出材料預算的必要原文供給、正式事件關係更正及擴展宿主證據。第二／第三層記憶、一般主動策略與完整代理平台只保留規劃，六方向如下保留；向量不是本單依賴。後續記憶層須承接可更正的來源／版本／理由效力，任務層須另核對執行授權、取消及完成證據，不能直接把目前計畫或投影當成工具執行許可。離線補發、永久授權與跨人共享仍須產品決策。使用者可由 GitHub 正式 tgz 自行選用與可逆更新；公開發布不等於日常部署已載入。

以下 0.1.0 段落保留前版範圍，與上方 0.1.1 累積增量分開。前版公開紀錄請核對 [GitHub Release](https://github.com/redwakame/CMCP-TIME/releases/tag/v0.1.0) 與 [npm 指定版本](https://www.npmjs.com/package/@redwakame-skill/cmcp-time/v/0.1.0)；0.1.1 的範圍與限制另見[四語版本說明](release-0.1.1.md)。

CMCP 採 Skill-first，保留宿主原生模型、工具與其他 Skills。原文、角色、來源版本、原時間與正式授權是依據；摘要、Buffer、索引及模型描述不能取代原件。控制、保存、閱讀、派送與顯示偏好分開。

## 正式首版關卡與後續

已核對的工程範圍包括資料匯出還原、容量滿／缺件、取消與重啟、Codex 同 Thread 原生 Context 壓縮、精確更新／解除及正常跨宿主文字往返。GUI、SDK、替身、同機程序與真正遠端證據分列；未受本次文件／版本整理影響的真宿主證據沿用，不為改版號重跑模型。

正式發布須固定同源版本與成品、四語文件／圖片、公開清單與脫敏、非作者路徑實包安裝，再核對 GitHub main／tag／Release 與 npm 版本／標籤／新下載包。來源 ZIP 與 npm 執行套件用途不同；雜湊映射見正式 Release 的外置清單。歷史候選紀錄見 [版本說明](release-0.1.0.md)，不代表目前 registry 狀態。

下一階段只由新工單安排。離線補發、永久授權、多人隔離及新資料外送仍需要明確產品決策。OpenClaw／dots／Grok Bot／Muse 的介面、審核與完整生命週期狀態見 [能力矩陣](interop-capabilities.zh-TW.md)，不以通用 MCP 支援代替具名實測。

### S1-R1：按需供給正式修訂契約

目前本機候選將初始來源責任與正式閱讀詳細契約分層：普通新問題仍直接回答，成功 open 才提供完整 v6 契約，原文、角色、時間、覆蓋及控制守護維持。這是供給接線改善，不代表自然語意必定正確；新候選的中間修訂、理由作用範圍與跨宿主語意須依同版原件另行裁決。正式版與日常部署保持，本單未完成不開下一階段。六項原始方向、完整代理與第二／第三層責任仍按既有章節保留，向量不作本輪依賴。

### S1-R1：來源用途待覆核

目前候選在同一正式來源／版本內檢查現況回報引文是否完全落在計畫狀態引文中。重疊只代表用途需要區分，不自動證明回報錯誤；待覆核保留完整原文、計畫與回報。合法混句可提供綁定該項 finding 及正式回報子句的明示解決；意圖或前提誤列則由原宿主更正，Core 不以關鍵詞自動分類。查看、部分結果與來源核對都不增加執行授權。

有限同版案例的實際裁決由配對交付報告列明；本機實作、來源驗證與自然語意不是同一層。未提供的材料、真正歧義、超過有界容量的查詢，以及尚未成立的外部狀態保持明示；不以錯列 unknown 代替明確原文條件。正式 0.1.0、日常部署及其餘六項方向不因此改變。

新的 v6 表示另分一般工作指令與計畫／事實，並將原話角色、原時間與引文用途放在目前回報旁，避免把來源中的我／你直接當成現在回答者。這些是共用來源／狀態契約的相容增量，不是新的任務授權；真宿主中間回合與最後接續仍須按相同判準核對。完成本單後，第二／第三層記憶與持久任務可沿此來源責任接續，未定政策仍不由投影自動補成。

### S1-R1：回答組裝、原時間與同訊息用途

候選的正式來源組裝保留 User 條件、回報與 Assistant 提案的分工；完整傳輸後的短契約不生成答案或新增採納關係。來源時間在同票券 metadata 以既有 formatter 與有效時區提供可核對值，原文仍保留原 UTC、角色、版本及 hash；本地時間不重複占用正文預算，未知時區不猜值，也不把訊息時間補成事件時間。

新的 v6 用途核對先保持既有 contained finding 與精確子句守護；沒有包含候選時，才對同一正式訊息／版本的不同狀態與回報引文提出待覆核。一則訊息不等於同一案件，更不等於回報有錯。真正回報須以目前已提的完整 ref／quote／range 明示解決，誤列的一般指令則回到 context，原計畫與條件保持。這些變更不以關鍵詞分類、不改 History，也不取得執行／Pin／派送權。

上述是本機實作與有界來源責任；零模型反例、來源／結構核對、中間回合及新宿主的自然語意分項舉證。最終通過與未通過以同版交付報告裁決，本節不預填 PASS。六項原始方向、完整代理及第二／第三層接續目標保持，向量不作本輪依賴，正式 0.1.0 與日常部署不自動變更。

### S1-R1：content 修改來源的用途提示

v6 候選另對每條已宣告 content 引文實算同來源用途差集：replacement 效果與已綁定修改版本的理由、同目標保留用途分列，並提供精確未用片段及原來源身分供宿主核對目前計畫。自我引用、ACK 或不同來源不會把提示變成已解決；未用片段可能只是對象、連接詞、標點或撤回指令，不自動判為條件遺漏、來源漏選或新的未知，也不設全字元覆蓋門檻。v1–v5 的入口與輸出行為保持。

提示沿現有 128／64 KiB 投影界限；不足時保留完整父材料，只明列提示因容量未評估，不當作零缺口或語意通過。已保存 C47 投影的容量測量、以原回執重建的機制 fixture 及原參數 replay 分開；原參數未提供時不補造它。此段記本機實作責任，測試、實包與真宿主是否改善仍待同版驗證，正式版和日常部署不自動切換。

### S1-R1：明示條件與適用對象的局部修訂

本機 C50 提供相容的 v7 選配表示：以正式引文宣告條件及適用對象，局部修改只更新指定對象，其他對象保留原值、來源、理由與狀態。它編譯回既有 v6／Core 路徑，沒有第二份 History；v6 入口及原有來源、角色、READ-ALL、版本、控制、容量與撤權守護保持。宣告的對象仍須由宿主理解，結構驗證不冒稱語意判決，也不產生執行、Pin 或派送授權。

原三缺陷的既有完整案例與新增 v7 正常接續，按實際相依差異分層舉證。C50 的五輪合成 Harness SDK → 乾淨 Hermes 流程已正常完成；中間修改正式狀態保留未改對象，後續可見回答分開局部暫停、User 完成回報、理由撤回與未採納建議。保留局部衍生草稿的 `partial`、未觀測投影的回合及未知層級，不把每輪工具成功或結構 `ready` 當成全部語意通過。最終需求閉合、獨立變體及交付裁決另見本機同版報告，這不是所有未來對話零錯誤的保證。

後續第二層個人／專案記憶、第三層語意延伸與完整代理，可重用正式 Pointer／版本、來源時間、目前計畫、回報與理由責任；持久任務、工具、核准與商業流程仍須各自的執行授權與產品決策。本輪不啟用這些外部能力。六項原始方向保留：多模態延伸、跨語搜尋與向量效益評估、並行／多人共享、一般主動及離線政策、觀測差異、可插拔儲存仍依各自證據安排；不自動進入下一階段、更新日常部署或發布研發候選。
